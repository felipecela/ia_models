#### **1. FIX: Token Truncation (CRÍTICA)**

El problema: `validate_and_truncate_messages()` no recalcula tokens después de truncar.

**Archivo:** proxy.py

**Cambio requerido:**
```python
def validate_and_truncate_messages(body: dict, nivel: str, model: str) -> dict:
    max_ctx = _MODEL_MAX_CTX.get(model, 16384)
    max_input_tokens = int(max_ctx * 0.8)
    
    estimated = estimate_body_tokens(body)
    
    if estimated <= max_input_tokens:
        log.debug("[V25-TOKEN] OK: %d tokens (max %d) en %s", 
                  estimated, max_input_tokens, model)
        return body
    
    log.warning("[V25-TOKEN] Exceso: %d > %d (%s/%s)",
                estimated, max_input_tokens, nivel, model)
    
    messages = body.get("messages", [])
    if not messages:
        return body
    
    # AQUÍ ESTÁ EL BUG: después de truncar, SIEMPRE recalcular
    system_msgs = [m for m in messages 
                   if isinstance(m, dict) and m.get("role") == "system"]
    user_msgs = [m for m in messages 
                 if isinstance(m, dict) and m.get("role") != "system"]
    
    # Estrategia mejorada: mantener último user + system,
    # pero iterar eliminando mensajes históricos si es necesario
    new_messages = system_msgs + (user_msgs[-1:] if user_msgs else [])
    body["messages"] = new_messages
    
    # ✅ RECALCULAR DESPUÉS DE CADA CAMBIO
    new_estimated = estimate_body_tokens(body)
    
    # Si aún excede, eliminar message content (último recurso)
    if new_estimated > max_input_tokens:
        for msg in new_messages:
            if isinstance(msg, dict) and msg.get("role") != "system":
                # Truncar content directamente
                content = msg.get("content", "")
                if isinstance(content, str):
                    # Reducir por palabras hasta caber
                    words = content.split()
                    while len(words) > 0 and estimate_body_tokens(body) > max_input_tokens:
                        words.pop()
                    msg["content"] = " ".join(words)
        new_estimated = estimate_body_tokens(body)
    
    log.info("[V25-TOKEN] Truncado: %d → %d tokens", estimated, new_estimated)
    return body
```

**EL ROUTER FUNCIONA PERFECTAMENTE** (localhost:8000 recibe respuestas):
```
curl localhost:8000 → ✅ "¡Hola! ¿Cómo puedo ayudarte hoy?"
```

**PERO OpenClaw NO RECIBE** → Esto significa:

OpenClaw está intentando conectar a una dirección **incorrecta**. Probablemente está usando:
- ❌ `127.0.0.1:8000` (solo funciona localmente)
- ❌ `localhost:8000` (resuelve a IPv6 `::1` que falla)

**SOLUCIÓN NECESARIA EN OpenClaw:**

Cambiar la configuración de OpenClaw para usar la **IP real de la máquina** donde corre el Router:

```
# Obtener IP de la máquina:
hostname -I

# Usar esa IP en OpenClaw, NO localhost:
http://[IP-REAL]:8000/v1/chat/completions
```

podria ser con 127.0.0.1? porque dependiendo de la red en la que me encuentre puede cambiar


RESPUESTA:
Sí, **`127.0.0.1:8000` es la solución correcta**.

El problema es que `localhost` intenta primero **IPv6 (::1)** que está rechazando conexiones, y luego fallback a IPv4. OpenClaw probablemente se queda en el primer intento fallido.

**SOLUCIÓN PARA OpenClaw:**

Configurar explícitamente:
```
http://127.0.0.1:8000/v1/chat/completions
```

**NO usar:**
- ❌ `localhost:8000` (intenta IPv6 primero)
- ❌ Nombres DNS que resuelvan diferente según la red

**VERIFICACIÓN RÁPIDA:**

```bash
# Esto funciona (IPv4 explícito):
curl http://127.0.0.1:8000/health | jq '.backends'

# Esto puede fallar (IPv6):
curl http://localhost:8000/health | jq '.backends'
```

**Para OpenClaw, usa siempre:**
```
ROUTER_URL=http://127.0.0.1:8000
```

Esto funcionará independientemente de la red porque `127.0.0.1` es **loopback IPv4 universal** - siempre apunta a localhost en tu máquina. 🎯
